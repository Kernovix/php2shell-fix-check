Linux

Bash script

Download .sh ↓

RUN WITH YOUR AUTHORIZED TARGETS

bash php_audit.sh '192.168.1.0/24' en

Replace 192.168.1.0/24 with your scope. Use pt for a Portuguese report. Without arguments, the script asks for both.

Requirements & optional SSH inventory

Bash 3.2+, curl 7.21+ with HTTPS, coreutils (including timeout and mktemp), awk, grep and sed.

For optional Linux inventory, use an existing SSH key or agent and verified host keys:

bash php_audit.sh '192.168.1.10' en --ssh-user auditor

No sudo or password prompts. Insufficient access leaves missing evidence inconclusive.

Windows

PowerShell script

Download .ps1 ↓

RUN WITH YOUR AUTHORIZED TARGETS

.\PHP-Audit.ps1 '192.168.1.0/24' en

Or open the script in PowerShell ISE and press F5. Enter your targets and choose en or pt when prompted.

Requirements & optional WinRM inventory

Windows PowerShell 5.1 with .NET Framework 4.7.2+, or PowerShell 7 on Windows. Follow your organization's script execution policy.

For optional Windows inventory, use existing authorized PowerShell Remoting:

.\PHP-Audit.ps1 '192.168.1.10' en -Credential (Get-Credential) -UseSSL

The script does not change WinRM, firewall rules or TrustedHosts.

READ THE RESULT CORRECTLY

Uncertainty stays visible.

No PHP detected does not mean no vulnerability. A CLI version or HTTP banner alone never proves that a website is fixed.

POTENTIALLY VULNERABLE

Investigate and prioritize.

An older PHP version needs review. Check vendor backports and confirm the web runtime before drawing a conclusion.

INCONCLUSIVE

More evidence is needed.

Missing versions, unreachable hosts and CLI-only findings remain inconclusive. A fixed-looking banner is insufficient too.

VULNERABLE / FIXED

Evidence must match.

Confirmed states require reviewed, matching web-runtime evidence for both CVEs. The tool does not automatically certify vendor backports or an entire server.

Coverage limits: name-based/SNI virtual hosts, proxies, hidden installations, other paths and restricted containers may be missed. Public exposure can be declared by the technician; it is not tested from the Internet.

A FEW IMPORTANT DETAILS

Before you run.

Does Fix Check apply patches?

No. It inventories services and collects evidence to support remediation decisions. It does not install, update, restart or change target servers. Plan and validate updates separately with your vendor.

Does it run exploits or stress tests?

No. Network discovery uses TCP checks and a bounded GET request to the root path. There are no exploits, DoS tests or WAF bypass attempts. Optional SSH and WinRM collection uses existing authorized access.

Do I need credentials?

No credentials are needed for web discovery. Remote Linux inventory uses SSH keys or an agent; remote Windows inventory uses existing WinRM access. Passwords are not written to the reports or logs.

Can I adjust ports and scan speed?

Yes. Defaults are 80, 443, 8080 and 8443, with eight concurrent workers and a limit of 4,096 IPv4 addresses. Use Bash --ports / --concurrency or PowerShell -Ports / -Concurrency. Consult the README for TLS ports and timeouts.

!

Authorized systems only. Obtain permission and agree the network scope before running an audit. Even read-only requests can appear in service logs and monitoring. This website does not scan your network or receive your reports.
